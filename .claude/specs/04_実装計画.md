# Eagle Grid Image Maker — 実装計画

- 版：v0.1（2026-11-23）
- 対応文書：[全体仕様書](./01_全体仕様書.md)／[画面構成仕様](./02_画面構成仕様_モックアップAI向け.md)／[技術検証事項](./03_技術検証事項.md)

## 1. 進め方

- 2章の段階 0〜6 の順に作る。1つの段階が終わるたびにユーザーに見てもらい、OK をもらってから次へ進む
- コミットは段階ごとか、それより細かく分ける
- 動作は、開発用のビルドにだけ入れる「リモート受付」で外から命令を送って確かめる（3.4）。本物の保存ダイアログや Cmd / Ctrl + ドラッグなど、手で触らないと確かめられないものはユーザーに頼む
- Eagle を操作・テストするのは、ライブラリの名前が **`test-library`** のときだけ。操作の前に毎回 `eagle.library.info().name` で確かめ、違えば止める。ほかのライブラリでのテストは禁止
- Windows（x64）用は Windows の PC でビルドする。Mac から Windows 用の sharp を取ってくる方法は使わない

## 2. 段階

### 段階 0：土台

- Vite ＋ Vue 3 ＋ TypeScript のひな形と manifest.json を作り、`npm run build` で `dist/` を作る
- 確かめること
  - Vite が出力する `<script type="module">` が `eagleplugin://` で動くか。動かなければ、モジュールを使わない形式で出力する
  - バンドルしたコードから Node の `require`（fs・path・sharp）を呼べるか
  - sharp 0.32.6 を `dist/node_modules` に入れて、実行時に読み込めるか
  - `eagle.app.locale` の値（日本語・英語の判定に使う）
- できあがり：Eagle で空の3カラムのウィンドウが開き、sharp のバージョンが表示される

### 段階 1：計算の部分（`src/core/`）

- 検証用の `tech-verify/js/layout.js` を参考に、TypeScript で書き直す
- 書き直すもの
  - 列数・行数の空欄の扱い、ページの切り出し、「右へ」「下へ」の並べ方
  - ヘッダーの共通の幅と高さ、軸タイトル（90° 回す）、ページをまたぐヘッダーの続き番号
  - Cover / Contain・小さい画像を拡大しない・向き揃えの計算（プレビューと書き出しで同じものを使う）
  - 並べ替え（`Intl.Collator`）、ランダム、挿入移動（落としたページの先頭に入れる規則）
  - 出力サイズの計算、形式ごとの上限の判定
- 文字の幅の測り方は外から渡す形にして、Canvas に依存しないようにする
- Vitest で単体テストを付ける

### 段階 2：Eagle とのやり取りと状態

- 起動したときに選択中の画像を読み込む。読めなかった画像は一覧にし、収まらない分は警告する
- 再読み込み：手動順なら末尾に足し、ランダムなら新しい分だけランダムな位置に入れる。編集状態は引き継ぐ
- 除外した ID を覚え、「グリッドをクリア」で忘れる
- 設定を自動で保存し、起動したときに戻す

### 段階 3：画面の骨組みと設定

- 3カラム、右上と右下の決まったボタンの並び
- 5つのカテゴリ（グリッド・画像・テキスト・外観・書き出し）の設定欄
- ヘッダーの入力欄（行番号つき、最大 10 行、外の箱でスクロール。01 の 6.5）
- フォントの一覧（`queryLocalFonts()`。止まったら打ち切る）
- 日本語と英語の切り替え（3.3）
- 見た目は、確認が済んだモックアップに合わせる

### 段階 4：プレビュー

- 検証用の `tech-verify/js/tests-preview.js` の `PreviewView` を参考に書き直す
- サムネイルで1ページを描く。キャッシュは1ページ分まで
- Fit・ズーム・パン・ページ送り
- 削除モード（確認ダイアログを出す）、Cmd / Ctrl + ドラッグでの挿入移動
- 空・読み込み中・エラーの表示

### 段階 5：書き出し

- 検証用の `tech-verify/js/engine.js` を参考に書き直す。方式は、TV-07 でいちばん速かった memory 方式にする
- sharp のキャッシュと並列数を絞る（01 の 8.2）
- 保存ダイアログ、全ページのファイル名で同名を調べる（上書き・別の番号・やめる）
- 文字は Canvas で描いて合成する
- 進み具合の表示と中止。失敗したときは書きかけのファイルだけを消す。`fs` で書いて、エラーの種類で表示を決める
- 出力サイズの表示と警告。必ず失敗するときは保存できなくする
- ここで確かめること
  - JPEG の寸法の上限（モックは 65,535px で計算している）
  - 「重い」警告の目安（モックでは1ページ 400MB）
  - 03 の 10.3 で残っている3つ（セル 2000 以上の合成、写真のような画像、ディスクが足りないとき）

### 段階 6：仕上げと配布

- Windows の PC でビルドし、動きを確かめる
- OS ごとの manifest（`platform` と `arch`）、「Pack Plugin」で `.eagleplugin` を作る手順

## 3. 決めたこと

### 3.1 名前

- プラグインの名前：Eagle Grid Image Maker
- プラグインの ID：`eagle-grid-image-maker`

### 3.2 フォルダの構成

```text
（リポジトリの直下）
├─ package.json / vite.config.ts / tsconfig.json
├─ public/            manifest.json・ロゴ（そのまま dist/ にコピー）
│  └─ locales/       言語ごとの文言（ja.json・en.json）。バンドルせず dist/locales/ に置く
├─ scripts/           sharp を dist/ に入れるスクリプトなど
├─ src/
│  ├─ core/           計算だけをする部分。Eagle・DOM・Node に依存しない
│  ├─ eagle/          Eagle API とのやり取り
│  ├─ state/          画像の並び・除外した ID・設定の保存と復元
│  ├─ preview/        プレビューの Canvas 描画・サムネイルのキャッシュ・パンとズーム
│  ├─ export/         sharp での書き出し・文字の画像化・ファイルの書き込み
│  ├─ i18n/           文言ファイルの読み込みと、文言を引く関数
│  └─ components/     Vue の画面部品
└─ dist/              ビルドしたもの＝Eagle に読み込むプラグインのフォルダ（gitignore）
```

- 状態の管理には Pinia を使わず、Vue の `reactive` で書く。依存するパッケージを増やさないため
- 設定は `localStorage` に保存する。TV-13 では再起動のあとに読めた。プラグインのフォルダは更新すると置き換わるので、保存先に使わない

### 3.3 言語

- 初期版は日本語と英語に対応する。あとから言語を足せるようにする
- 文言はコードに直接書かず、言語ごとの JSON ファイル（`locales/ja.json`・`locales/en.json`）に書く。キーと文言の組にする
- 文言ファイルはバンドルしない。プラグインのフォルダの `locales/` に置き、実行時に読み込む。言語を足すときは、ファイルを1つ置けばよく、ビルドし直さなくてよい
- 言語は Eagle の言語設定（`eagle.app.locale`）から決める。その言語のファイルがなければ英語にする。ファイルにないキーも英語の文言を使う
- 画面の中に、言語を切り替える設定は作らない

### 3.4 開発用のリモート受付

- 検証用プラグインの「リモート受付」と同じ仕組みを、開発用のビルドにだけ入れる。配布用のビルドには入れない
- 127.0.0.1 だけで待ち受け、合言葉（トークン）が合う命令だけを実行する

### 3.5 テスト

- `src/core/` に Vitest の単体テストを付ける

## 4. 段階ごとの結果

### 段階 0（2026-11-23、macOS）

- Vite が出力する `<script type="module">` は、Eagle の中でそのまま動いた。モジュールを使わない形式にしなくてよい
- ページの URL は `file:///…/dist/index.html?theme=DARK&locale=ja_JP` の形だった（開発用に読み込んだプラグイン）。パスは URL のパス部分から求め、クエリは使わない
- `eagle.app.locale` は `ja_JP`。`ja.json` が選ばれた
- sharp 0.32.6 は `dist/node_modules` から読み込めた。初めて読んだときは 894ms、画面を読み込み直したあとは 27ms
- 配布用のビルド（`npm run build`）には、開発用のリモート受付が入らないことを確かめた
- 開発の手順
  - ビルドには Node 18 以上が要る（Vite 6）。Eagle の中の Node 16 とは別
  - `npm run dev` でファイルを変えるたびに `dist/` を作り直す。Eagle には `dist/` を「ローカルプロジェクトをインポート」で読み込む
  - 開発用のリモート受付の接続の情報は `.cache/remote.json`
- 残したこと：sharp 0.32 はインストールに使うパッケージも入るので、`dist/node_modules` が 34MB ある。省くのは段階 6

### 段階 1（2026-11-23）

- `src/core/` に、計算だけをする部分を作った。Eagle・DOM・Node に依存しない。単体テストは 81 件（`src/` 全体で 92 件）
  - `settings.ts`：設定の型と初期値
  - `grid.ts`：列数・行数（空欄の扱い）、ページ数、入力できる枚数、ヘッダーの続き番号
  - `layout.ts`：ページの大きさ、セル・タイトル・ヘッダー・軸タイトルの位置。寸法は全ページで共通
  - `placement.ts`：Cover / Contain・小さい画像を拡大しない・向き揃え
  - `order.ts`：並べ替え・シャッフル・挿入移動・再読み込みのときの合わせ方・取り込む枚数の上限
  - `text.ts`：フォントの指定・折り返し
  - `limits.ts`：保存できるかの判定（0 枚・32 ページに入りきらない・形式の寸法の上限・「重い」警告）
- モックアップに合わせたこと
  - XY プロットの ON / OFF の設定を持つ。初期値は OFF
  - 品質は JPEG と WebP で共通の1つ
  - 32 ページを超えた分は表示しない。はみ出した枚数を警告し、保存できなくする
  - 「重い」警告の目安は、1ページを RGBA で持ったときに 400MB（段階 5 で見直す）
- 仮に決めたこと（ユーザーに確認する）
  - 軸タイトルが空なら、その場所を取らない
  - タイトルがグリッドより広いときは、全体を広げて、中身を左右の中央に置く
  - 軸タイトルは折り返さない（1行）
- ファイル名順：`Intl.Collator('ja', { numeric: true })` は「画像あ」と「画像ア」を同じとみなす（Node 22・Eagle の Chrome 108 とも）。同じ値どうしは選択順にする

### 段階 2（2026-11-23、macOS）

- 作ったもの
  - `src/eagle/adapter.ts`：選択中の画像を受け取り、`GridItem` に直す。対応していない形式・元画像がないものは飛ばして、一覧にする
  - `src/state/settings-store.ts`：設定を `localStorage` に自動で保存し、起動したときに戻す。読み込むときに値を1つずつ確かめ、おかしい値は初期値に戻す
  - `src/state/grid-store.ts`：画像の並び。起動したときの読み込み・再読み込み・除外・クリア・挿入移動・並べ替え
- 決めたこと
  - 再読み込みで入力できる枚数を超えるときは、今グリッドにある画像を残し、新しい画像だけを選択順に入る分まで足す（並べ替えた結果、今ある画像が押し出されて消えないようにするため）
  - 並び順は設定として保存する。起動したときに「手動順」なら選択順で並べ、「ランダム」なら1度シャッフルする
  - 壊れた画像は、読み込みの時点では分からない（開かないと分からない）。プレビューや書き出しで開けなかったときに扱う
- Eagle（test-library）で確かめたこと
  - 起動したときに、選んだ順のまま読み込める
  - 並べ替え・ランダム（選んだときだけ）・挿入移動のあとの手動順・再読み込み（手動順は末尾に追加）・除外した画像を再追加しない・クリアで忘れる
  - 対応していない形式（SVG）と元画像がない画像を飛ばし、理由と一緒に一覧にする
  - 設定は画面を読み込み直しても残る
  - 8,192 件の読み込み 176ms、再読み込み 169ms、ファイル名順の並べ替え 6ms
  - 入力できる枚数を超えたら、先頭から入る分だけを取り込む（4 列×2 行なら 256 枚、4 列で行が空欄なら 2,048 枚）
- test-library に足したもの：対応していない形式の確認用の SVG 1枚（タグ `egim-dev`）

### 段階 3（2026-11-23、macOS）

- 作ったもの
  - 3カラムの画面（左：カテゴリ、中央：設定、右：プレビュー）、右上と右下のボタン（並びは仕様のとおり）
  - 5つの設定欄（グリッド・画像・テキスト・外観・書き出し）。見た目と文言はモックアップに合わせた
  - ヘッダーの入力欄（行番号つき・最大 10 行・外の箱だけがスクロール・行番号は sticky）
  - フォントの一覧（`queryLocalFonts()`。2 秒で打ち切る）。総称フォント（ゴシック・明朝・等幅）のあとに OS のフォントを並べる
  - 確認ダイアログ（再読み込み・削除モードで外す・クリア・読み込めなかった画像の一覧）
  - 書き出しの設定欄に、出力解像度・ページ数・推定メモリと、上限・「重い」の警告。プレビューの上に、取り込めなかった枚数・32 ページに入りきらない枚数・形式の上限の帯
  - 文言は `ja.json`・`en.json` に 114 件。2つのファイルでキーと差し込みがそろっているかをテストで確かめる
- 仮のもの：プレビューはセルを灰色の四角で描くだけ。拡大・縮小は倍率を変えるだけ（段階 4 で作り直す）
- モックアップと変えたところ
  - モックアップの上の「タイトルバー」は作らない。Eagle のウィンドウの枠にプラグインの名前が出るため
  - 背景色・文字の色の色見本を押すと、OS の色選択が開く
  - 配置方向を切り替えて、必須になった側が空欄なら 4 を入れる（モックアップの計算と同じ）
- Eagle で確かめたこと：フォントは 413 件取れた。上の画面とダイアログが表示され、設定がプレビューと出力サイズに反映される
- 開発用のリモート受付に `R.snapDom(path)` を足した。画面の HTML を SVG に包んで PNG にする（`@electron/remote` の `capturePage` はプラグインでは使えなかった）
- 残したこと：「キャンセル」でウィンドウを閉じる（`window.close()`。閉じられなければ `eagle.window.hide()`）は、ユーザーに押して確かめてもらう
