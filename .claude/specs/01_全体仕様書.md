## 1. 目的・適用範囲

Eagleで現在選択している静止画・GIFをグリッド上に配置し、通常のコンタクトシートまたは行・列を比較するXYプロットとして書き出す。プレビューと最終書き出しは異なる画像ソース・処理を用いるが、同一の配置定義を共有する。

想定する主な使い方は、生成した画像（例：832×1088）を比較用に並べるXYプロット。列数と行数を入れ替えるだけで、軸を入れ替えられるようにする。

### 1.1 コア要件 [確定]

1. 対象入力：**JPEG / PNG / WebP / GIF**。GIFは**先頭フレームだけ**を使用する。
2. 出力：**JPEG / PNG / WebP**。アニメーションGIF出力はしない。
3. セルの既定値は**320×320 px**、幅・高さをユーザー指定可能。
4. プレビューはEagleのサムネイルを使い、**320×320 pxを基準とするプレビュー処理**とする。プレビューでズームしても元画像に切り替えない。
5. 実際の書き出しでは**元画像を個別に読み込んで変換し、確定したセル位置に配置**する。プレビュー用Canvasを拡大して出力しない。
6. 最大**16列×16行／ページ**、最大**32ページ**、理論上の最大**8,192枚**。収容可能枚数は列数・行数の設定で変わる。
7. 設定値は自動保存・次回起動時に復元。**前回の画像リストは復元しない**。
8. UIは既存「Image Export Studio」に近い**左カテゴリ／中央設定／右プレビュー**の3カラム。

## 2. 入力データと状態管理

### 2.1 初期読み込み [確定]

- プラグイン起動時にEagleで**現在選択中の画像**を取得する。前回の画像セットを復元しない。
- 各項目に少なくとも以下を保持する：EagleアイテムID、元画像参照先、サムネイル参照先、ファイル名、登録時刻、入力形式、元画像サイズ（取得可能な場合）。
- アイテムIDを同一画像のキーとして扱う。
- Eagleサムネイルはページごとに必要なものだけ取得・利用する。例として、832×1088 / 1664×2176の元画像に対し320×418サムネイルが確認されているが、**その寸法を固定条件にしない**。
- 選択数0件、非対応形式、欠損ファイル、破損サムネイルに対してUIの例外状態を用意する。
- 読み込めない画像（非対応形式・ファイルがない・壊れている）は**飛ばして読み込みを続け**、終わったら失敗した画像の一覧を表示する。途中で止めない。
- 収容可能枚数（4章）を超える選択が来たときは、**先頭から収まる分だけを取り込み**、取り込めなかった枚数を警告する。

### 2.2 再読み込み [確定]

- 右カラム上部の**再読み込みアイコン** → **確認ダイアログ** → Eagleの現在の選択リストを再取得。
- 新規項目の追加位置：
  - 並び順が「手動順」なら**末尾に追加**。
  - 「ランダム」なら、**今の並びはそのままにして、新規項目だけをランダムな位置に挿入**する。全体を並べ替え直さない。
  - その他は**現在の並び順に従う**。
- 既存IDに紐づく**個別編集状態を引き継ぐ**。将来のセル内位置・ズーム・回転も同一IDで保持可能なデータ構造にする。
- グリッドから除外した項目は、Eagleで再び選ばれていても**再追加しない**。除外したアイテムIDを覚えておき、「グリッドをクリア」で忘れる。

### 2.3 画像の除外と全クリア [確定]

- 右上の**ゴミ箱アイコン**で「削除モード」をON/OFFする。
- ON時にセルを個別クリック → **確認ダイアログ** → 対象をグリッドから除外。
- 右下の**「グリッドをクリア」** → **確認ダイアログ** → グリッド内の画像をすべて除外する。あわせて、除外したアイテムIDの記憶（2.2）も消す。
- いずれもEagleライブラリ内の元ファイルは削除しない。

## 4. グリッド配置・ページネーション

| 設定 | 仕様 | 状態 |
|---|---|---|
| セル幅／高さ | それぞれ任意のpx値。デフォルト320×320 | [確定] |
| 列数 | 1〜16。「左上→右へ」では必須。「左上→下へ」では空欄にできる | [確定] |
| 行数（1ページ） | 1〜16。「左上→下へ」では必須。「左上→右へ」では空欄にできる | [確定] |
| 配置の流れ | 左上→右へ／左上→下へ | [確定] |
| 最大ページ数 | 32ページ | [確定] |
| ページの上限 | 16×16＝256セル／ページ | [確定] |
| 1ページの収容枚数 | 列数×行数。空欄の側は16として計算する | [確定] |
| 入力可能枚数 | 1ページの収容枚数×32ページ。最大8,192 | [確定] |
| 画像不足時 | 余った位置にセルを生成しない（下記のとおり、場所は確保して背景色のままにする） | [確定] |
| セル間ギャップ | px値で指定可能 | [確定] |
| 外周余白 | px値で指定可能 | [確定] |
| 背景色 | 指定可能 | [確定] |

**空欄の扱い** [確定]

- 空欄の側は、**全体の枚数から決めて全ページで同じ値**にする。値は `min(16, ceil(全体の枚数 ÷ 必須の側の数))`。
- 例：左上→右へ・4列・行数は空欄のとき
  - 10枚なら3行の1ページ
  - 100枚なら、どのページも16行の2ページ（2ページ目は36枚で、残りは空き）

**ページの大きさ** [確定]

- 配置の流れにかかわらず、**どのページも「列数×行数」の大きさに揃える**。最後のページも同じ大きさにする。
- 画像が足りない位置にも**セルの場所を確保する**が、そこには何も描かず背景色のままにする。
- 画像が列数より少ないときも、設定した列数の幅を保つ（CSSの `grid-template-columns: repeat(列数, セル幅)` に相当）。比較するときに大きさが変わらないようにするため。
- 「左上→下へ」では、各列を上から行数の分だけ埋めてから次の列へ進む。行数は設定した値で固定し、枚数から詰め直さない。

**ページ送り** [確定]

- 右カラム下部に `[◀][▶] Page n / N` を表示し、プレビューをページ単位で切り替える。
- ページ境界をまたぐ並べ替えでも、全体順序の正しさを維持する。[実装要件]
- 枚数や列数・行数が変わってページ数が減り、表示していたページがなくなったときは、**最後のページへ移る**。
- 列数・行数を減らして入力可能枚数を超えたときは、はみ出した画像を**外さずに保持**する。その間は保存ボタンを押せなくし、警告を表示する。

## 5. セル内画像の変換

| 設定 | 内容 | 状態 |
|---|---|---|
| Cover | セル全域を満たす。必要ならはみ出しを切り抜く | [確定] |
| Contain | 画像全体をセル内に納める | [確定] |
| 小画像の拡大 | セルより小さい画像を拡大する／しない | [確定] |
| 自動向き揃え | 回転しない／縦長に合わせる／横長に合わせる | [確定] |
| 回転方向 | 90°の時計回り／反時計回りを選択 | [確定] |

- 「縦長に合わせる」では横長画像を90°回転、「横長に合わせる」では縦長画像を90°回転して、可能な限り向きを統一する。[確定]
- Cover / Containと「小さい画像を拡大しない」の組合せで生じる余白・実描画範囲は**同一の変換計算**からプレビュー／出力へ反映する。[実装要件]
- EXIF Orientationを反映し、GIFは先頭フレームを使う（TV-08で確認済み）。
- セルごとの**手動回転・位置調整・ズーム・リセットは保留**（操作規約のみ後述）。

## 6. テキストとXYプロット

この章の見せ方（揃え方・配置・余白）は、実際に使ってみて違和感があれば見直す。[確定：初期版の仕様]

### 6.1 グリッド全体のタイトル [確定]

- 1行タイトル文字列を設定可能（改行不可）。空欄なら表示せず、タイトルの領域も作らない。
- フォントファミリーとフォントサイズを選択可能。フォントは OS にインストールされているものから選ぶ（6.4）。
- 横の位置は**中央に固定**する。設定項目は作らない。
- タイトル領域の高さは文字の描画高さで決める。直下余白は**`0.5em`**。

### 6.2 XYプロットの個別ヘッダー [確定]

- **列ごとに異なる上部ヘッダー**、**行ごとに異なる左側ヘッダー**を入力できる。
- 横軸・縦軸の**軸タイトル**も付けられる。
- 個別ヘッダー用のフォントファミリー・フォントサイズを指定可能。軸タイトルもこのフォント・文字サイズを使う（設定項目を増やさない）。

**行ヘッダー（左側、各行対応）**：下記を**レイアウト上の意味を表す擬似CSS**として適用する。

```css
width: clamp(セル幅, 全行で最も広いテキスト幅, 100em); /* 全行で共通の幅 */
height: セル高さ;
align-items: center;         /* 上下は中央 */
justify-content: flex-end;   /* 左右は右揃え（グリッドに接する側） */
text-align: right;           /* 折り返したときの行も右揃え */
```

- 意図：行ヘッダーは最低セル幅を確保し、内容に応じて最大100emまで広げる。**全行で共通の幅**にして、グリッドの左端を揃える。短い行ヘッダーの左に余白ができるのは許容する。

**列ヘッダー（上側、各列対応）**：

```css
width: セル幅;
height: max(1em, 全列で最も高い折り返したテキストの高さ); /* 全列で共通の高さ */
align-items: flex-end;       /* 上下は下揃え（グリッドに接する側） */
justify-content: center;     /* 左右は中央 */
text-align: center;          /* 折り返したときの行も中央 */
```

- 意図：列ヘッダー幅はセル幅に合わせ、テキストを折り返す。**全列で共通の高さ**にする。
- 上記は実際にそのまま適用できるCSSではなく、画像の描画エンジン側でも同じ寸法規則を実装する。

**軸タイトル**

- 横軸タイトル：列ヘッダーの上に置き、セルの範囲の左右中央に揃える。
- 縦軸タイトル：行ヘッダーの左に、横書きの文字列を**時計回りに90°回して**置く（上から下へ読む向き）。日本語も英数字もまとめて回す。セルの範囲の上下中央に揃える。
  - 縦書きにしない。書き出しの文字はCanvasで描くが、Canvasには縦書きの機能がなく、縦書きの中の英数字の扱いで問題が出るため。
- ヘッダーとの間隔は`0.5em`。

**複数ページのとき**

- タイトル・軸タイトルは、**全ページに載せる**。
- 並びが進む側のヘッダーは、ページをまたいで**続きの番号**で付ける。もう一方のヘッダーは、**全ページに同じもの**を載せる。
  - 左上→右へ：ページが進むと行が続くので、行ヘッダーを続きの番号にする。列ヘッダーは全ページ同じ。例：1ページ4行なら、2ページ目の1行目には5番目の行ヘッダーを付ける。
  - 左上→下へ：ページが進むと列が続くので、列ヘッダーを続きの番号にする。行ヘッダーは全ページ同じ。例：1ページ4列なら、2ページ目の1列目には5番目の列ヘッダーを付ける。

### 6.3 文字の色 [確定]

- タイトル・ヘッダー・軸タイトルに共通の**文字の色**を1つ指定できる。初期値は黒。

### 6.4 フォントの選択肢 [確定]

- OS にインストールされているフォントから選ぶ。一覧は `queryLocalFonts()` で取る。
- `queryLocalFonts()` は許可を待ったまま止まることがある（TV-12）。一定時間（検証では2秒）で打ち切り、取れなかったときは既定のフォント（`sans-serif` など）だけを選べるようにする。

### 6.5 ヘッダーの入力欄 [確定]

- 列ヘッダー・行ヘッダーは、それぞれ**1つのテキストエリアに1行1見出し**で入力する。
- 入力欄の左に行番号を表示する。
- 入力欄の高さは**最大10行分**。それより多い行はスクロールして見る。
  - ページをまたいで続く側のヘッダーは、最大512行（16行×32ページ）になるため。
- 行番号はテキストと**一緒にスクロール**させる。作り方：
  - 高さが最大10行の外の箱（`overflow-y: auto`）の中に、行番号の列とテキストエリアを横に並べる。
  - テキストエリアは中身の行数に合わせて高さを伸ばし、中では縦にスクロールさせない。縦にスクロールするのは外の箱だけ。
  - テキストエリアの高さは、入力のたびに JavaScript で合わせる。高さを自動で伸ばす CSS の `field-sizing: content` は Chromium 123 からで、Eagle（Chromium 108）では使えない。
  - テキストエリアは折り返さない（`wrap="off"`）。折り返すと行番号とずれる。長い見出しはテキストエリアの中で横にスクロールする。

## 7. プレビュー仕様 [確定]

1. プレビュー画像は**Eagleサムネイル**を使う。元画像を高解像度でプレビューに読み込まない。
2. プレビューの**基準サイズは320×320**。実際のEagleサムネイルは縦横比を維持した別解像度で構わない。
   - Eagleのサムネイルは短辺320px。セルを埋めるときに拡大されてぼやけるのは許容する。
   - 長辺960px以下の画像には、Eagleがサムネイルを作らない（サムネイルの参照先が元画像になる）。この場合はプレビューでも元画像を使う。
3. 起動時およびページ表示時に**グリッド全体が表示領域に収まる倍率（Fit）**へ調整。
4. 通常ドラッグはプレビュー全体の**パン**、通常ホイールはプレビュー全体の**ズーム**。
5. Ctrl / Cmd + ドラッグは画像を**任意の位置に挿入移動**。
6. ページ切り替え中は必要サムネイルだけ読み込み、非表示ページのキャッシュを制限する。
7. プレビュー倍率に応じて見かけは拡大されるが、表示用画像そのものの元解像度は切り替えない。

## 8. 出力仕様

### 8.1 設定・保存動作 [確定]

- 出力フォーマットは**JPEG / PNG / WebP**から選択。
- JPEG / WebPは品質値を指定可能。
- 出力に使用するのは**Eagleの元画像**。各元画像を必要に応じて回転・リサイズ・クロップしてセル位置に合成する。
- 出力フォルダの**固定設定欄は設けない**。`グリッド保存`時に保存先を決める。
- その時点の設定・セルの並び・テキスト情報から、各ページの出力解像度を計算して表示する。

**ファイル名と連番**

- 保存ダイアログに最初から入れておく名前は `grid`。
- 複数ページなら**別ファイル**とし、`<名前>_01.<拡張子>` の形で**2桁の連番**を付ける（最大32ページなので2桁で足りる）。
- 1ページだけのときは連番を付けない（`<名前>.<拡張子>`）。

**同じ名前のファイルがあるとき**

- 保存ダイアログが確かめるのは入力した1つの名前だけなので、書き出す前に**全ページのファイル名**を調べる。
- 1つでもぶつかったら、次の3つから選んでもらう。
  - 上書きする
  - 別の番号にする（例：`grid-2_01.png`）
  - やめる

### 8.2 サイズとメモリに関する要件

- ユーザー指定の当初方針：**JPEGを基準にサイズを計算**し、出力形式を変更した結果その形式の上限を超えるなら**警告**する。[確定した意図]
- 形式の規格上限と画像処理エンコーダーの上限は一致しないので、上限は検証で測った値を使う（WebPは幅・高さとも16383px。03の10章）。
- 最大幅・高さ・総画素数・一時メモリ／ディスク使用量を事前に見積もる。[確定の制限方針]
- 制限に当たったときの扱い [確定]
  - 書き出すと必ず失敗する上限（形式の寸法上限など）を超えるときは、**保存ボタンを押せなくして**警告する。
  - それ以外の目安（総画素数やメモリの見積もり）を超えるときは、警告だけを出す。保存はできる。
  - **自動で縮小する機能は作らない**。セルを小さくするなど、ユーザーに直してもらう。
- プレビュー表示用Canvasの拡大書き出しは禁止。最終画像はsharp（libvips）で合成する。入力の逐次処理だけで巨大ページ全体のメモリが不要になるわけではない。
- sharpは一度確保したメモリを返さないことがある（主にmacOS。03の10.4）。初期版では、**sharpのキャッシュと並列数を絞ってメモリのピークを下げる**。書き出しを別のプロセスで行う方法は、メモリが実際に問題になったときに検討する。[確定]

### 8.3 失敗・中断 [確定]

- 書き出しが途中で失敗したときは、**書き終えたページは残し、書きかけのファイルだけを消す**。何ページ目で失敗したかを表示する。
  - 上書きを選んだ場合は元のファイルを戻せないので、全体を元に戻す（ロールバックする）方式は取らない。
- 書き出しの途中でやめられるようにする。やめたときの後片付けは、失敗したときと同じにする。
- エラーの表示は、sharpのメッセージをそのまま出さない（Windowsでは文字化けする。03の11.3）。ファイルの書き込みはNodeの`fs`で行い、エラーの種類（`EPERM`など）で表示を決める。

## 9. UI構成の要点 [確定]

- 左：カテゴリ選択アイコン。
- 中央：現在カテゴリのパラメータ。
- 右：画像リストの代わりに**グリッドプレビュー**。
- 右上はサブ操作、右下は情報＋メイン操作。位置と順序は以下を優先する。

```text
右上（右寄せ）： [再読み込み] [ゴミ箱] | [Fit] [-] [+]
右下：[◀][▶] Page <現ページ> / <総ページ> | <画像枚数>枚 | <現在の並び順> |
                                               [グリッドをクリア] [キャンセル] [グリッド保存]
```

- `キャンセル`は、ふだんはウィンドウを閉じる。設定は自動で保存しているので、確認は出さない。書き出しの途中では「書き出しをやめる」ボタンとして働く（8.3）。
- 中央設定カテゴリ案：**グリッド／画像／テキスト／外観／書き出し**。カテゴリ名・アイコン・一部補助UIはモックアップ段階の提案。[提案]
- 詳細は別紙「画面構成仕様」を参照。

## 11. 技術スタックと推奨アーキテクチャ

### 11.1 技術スタック [確定]

| 項目 | 決定 |
|---|---|
| プラグインの種類 | Eagle 4.0 のウィンドウ型プラグイン（Electron 22・Node 16.17・Chromium 108） |
| UI | Vue 3 ＋ TypeScript |
| ビルド | Vite。sharp はバンドルせず、実行時に `require` で読み込む |
| 画像処理 | sharp 0.32.6（0.33 以降は Node 18 以上が必要で使えない） |
| 対応環境 | macOS（Apple Silicon・arm64）、Windows（x64）。Intel の Mac と ARM 版の Windows は対応しない |
| 配布 | GitHub の Releases。プラグインセンターには出さない |
| 配布ファイル | OS ごとに `.eagleplugin` を1つずつ作る。manifest.json の `platform`（`mac` / `win`）と `arch`（`arm` / `x64`）を OS ごとに設定する |
| リリースの作り方 | 手作業。ビルドしたフォルダを Eagle に読み込み、「Pack Plugin」で `.eagleplugin` を作る。GitHub Actions は使わない |

- sharp の Windows 用のバイナリを Mac で取ってこられるか（`npm install --platform=win32 --arch=x64`）は、実装のときに確かめる。できなければ、Windows 用は Windows でビルドする

### 11.2 実装の境界と推奨アーキテクチャ [提案]

分割モジュールの例：

1. **Eagle Adapter**：選択・アイテムID・サムネイル／元画像参照を取得。
2. **Grid State**：アイテム順序、個別編集状態、設定、自動復元を管理。
3. **Layout Engine**：セル座標、行列ヘッダー、軸タイトル、ページの座標を一元計算。
4. **Preview Renderer**：Eagleサムネイルだけで1ページを低負荷表示。パン／ズーム／ページ送り。
5. **Export Renderer**：元画像を個別変換し、レイアウト結果に従って出力ファイルを生成。
6. **Validation**：各出力形式・エンコーダー・メモリ・ページ上限を判定。

**単一のレイアウトモデル**をプレビュー／書き出しで共有する。画像変換系の回転・EXIFや文字計測の差を放置しないこと。
